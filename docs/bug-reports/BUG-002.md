# BUG-002: Order quantity not range-checked (0, negative and >1000 accepted)

## Description
Order quantity not range-checked (0, negative and >1000 accepted).

**Code location:** OrderController::store - quantity rule is 'required|integer' (min/max removed)

## Steps to reproduce
1. POST /api/orders with items[0].quantity = 0, -5 or 1001

## Expected result
422 (allowed range 1..1000)

## Actual result
201 Created; zero/negative quantities and totals are stored

## Detected by
- Postman: Quantity 0 / -5 / 1001
- JUnit: OrderApiTest.invalidQuantity
- Cypress: orders.cy.ts quantity 0
- PL/SQL: QTY_POSITIVE

## Suggested fix
Restore 'required|integer|min:1|max:1000'. Add a DB CHECK constraint as defence in depth.

## Retest
`FIXED_BUGS=BUG-002` (restart the api container) turns off only this bug.
Re-run the tests listed under *Detected by*: they must pass, and the rest of the regression suite must stay green.
